Challenge contract

The seam between play and pedagogy

A game describes its context; the engine returns an objective-mapped challenge. The game reports evidence without deciding that a learner has “mastered” a skill.

Game → engine
{
  "game": "blocksmith",
  "phase": "plan-wall",
  "skills": ["multiplication"],
  "maxSeconds": 45,
  "supports": ["visual"]
}
Engine → game
{
  "objectiveId": "ENG-M-Y3-MUL-01",
  "prompt": "4 rows of 8?",
  "interaction": "choice",
  "feedback": { "mode": "worked" }
}
Game → evidence
{
  "objectiveId": "ENG-M-Y3-MUL-01",
  "correct": true,
  "attempts": 1,
  "supportUsed": false
}

Non-negotiable boundaries

Privacy and safeguarding are platform capabilities.

  • Guest firstPlayable without an account; progress can stay on device.
  • No open chatUse curated collaboration signals for children aged 7–10.
  • No behavioural adsNo ad tech, loot boxes or paid random rewards.
  • Explain adaptationChildren and adults can see why a skill is being revisited.
